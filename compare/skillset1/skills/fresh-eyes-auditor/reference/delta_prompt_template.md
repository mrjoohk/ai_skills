## 관점 점검표
[delta_lenses.md 의 해당 관점 부록을 그대로 붙인다]

## 심각도 (드리프트 금지 — 이 정의 외 해석 금지)
- HIGH (= CRITICAL): 현실적인 입력에서 잘못된 결과·중단·데이터 손실, 또는 검증 증적(시험·실측 기록)이 결함을 못 잡게 됨
- MEDIUM (= WARN): 경계·드문 입력에서 잘못된 결과, 빠진 보호(오류 처리·시간 제한), 설계-코드 불일치
- LOW (= INFO): 위험 낮은 결함, 시험 빈틈 중 덜 중요한 것, 표기·사문
프로젝트 대장이 CRITICAL/WARN/INFO 를 쓰면 괄호 안 이름으로 적는다.

## 규칙
1. 발견마다 file:line + 원문 인용과 **재현: 입력 → 관찰 vs 기대**(탐침 스크립트 경로). 재현하지 못한 것은 PLAUSIBLE 로 표시한다.
2. 결함이 아니라고 보는 설계상 선택(역전·근사·범위 밖 경우 등)도 '설계 메모'로 따로 적고, 대표 입력의 수치 예를 붙인다.
3. 다른 관점의 일은 깊이 하지 않는다 — 보이면 한 줄로 넘긴다.
4. 스타일 취향은 보고하지 않는다. 고칠 수 있는 실질 결함만.

## 출력 형식 (보고 파일)
# Delta round [n] — [관점] 보고
### 발견

  위치: <path>:<line> / 인용: "<원문>"
  재현: <입력 → 관찰 vs 기대> (탐침: <경로>) / 제안(1~2문장)
### 설계 메모 (결함 아님 — 그러나 처분 대상)
- ID: D[n]-[관점번호]-N01 / 요지 / 대표 입력의 수치 예
### 확인한 것 (문제없음)
- <무엇을 어떻게 확인했는지 한 줄씩>
### 커버리지
- 읽은 파일 / 돌린 탐침 / 못 본 것과 사유
