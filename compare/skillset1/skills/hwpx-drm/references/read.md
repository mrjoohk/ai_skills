# 읽기 — 명령·출력·위치 ID

## 명령

| 명령 | 하는 일 | 남는 .md |
|---|---|---|
| `inspect <파일>` | 요약·개요·필드·본문 전체(표 포함)·그림 위치·머리말/꼬리말·각주·메모 | `<md-dir>\<이름>.inspect.md` |
| `outline <파일>` | 개요 수준이 지정된 제목 문단만 | `<이름>.outline.md` |
| `tables <파일> [--table s0.t3]` | 표 전부(또는 하나)를 격자로 | `<이름>.tables.md` |
| `fields <파일>` | 입력 필드(누름틀·셀)와 한/글 필드 목록 대조 | `<이름>.fields.md` |
| `search <파일> --pattern 키1,키2` | 키워드별 위치 ID와 앞뒤 60자. 검색어 안의 쉼표는 `\,`(역슬래시 자체는 `\\`, 그 밖의 역슬래시는 그대로 — P-052) | `<이름>.search.md` |
| `verify <파일>` | 선두(DRM) 판정 + 한/글로 열리는지 | 없음 |
| `images <파일> --out-dir <새 폴더>` | 문서에 포함된 그림을 문서 차례로 `figKK.<형식>` **평문 파일**로(한/글이 내보낸 HWPML 의 그림 데이터 — Base64·압축 풂). 연결 그림·알 수 없는 형식은 건너뛰고 이유를 남김. drmHWP 결정 D-062(보안담당자 허락, P-052) | 그 폴더의 `images.md`·`images.json` |

- 화면에는 건수만 나온다. 내용은 .md를 읽는다. `--json`이면 결과 JSON도 화면에 낸다.
- 같은 명령을 다시 실행하면 같은 이름의 .md를 덮어쓴다.
- 읽기는 저장하지 않는다(문서를 닫을 때 변경 내용 버림).

## .md 구성 (inspect)

1. 머리: **DRM 미보호 평문 고지**, 원본 경로·선두 판정, 한/글·HWPML 버전, 소요 시간(open/export/parse 초)
2. `## 요약` — 구역, 문단 수(셀·각주 안 포함), 표(중첩 포함)·셀 수, 격자 불일치 표, 머리말/꼬리말, 각주/미주, 메모, 글상자, 필드
3. `## 개요` — 개요 문단(수준별 들여쓰기) + 위치 ID
4. `## 필드` — 이름·종류·개수·위치·현재 값·안내문(누름틀의 안내 문구)
5. `## 본문` — 문서 순서대로. 제목 문단은 `###`~, 일반 문단은 `` `s0.p12` · 스타일  글 ``, 표는 격자
6. `## 그림·개체 위치` (그림·도형이 있을 때) — 본문 글자에 없는 그림의 자리: 종류(PICTURE 등)·든 문단 ID·크기(mm)·캡션·앞 글
   (같은 구역에서 그 문단까지의 마지막 글). 화면 그림이 많은 설명서를 옮겨 쓸 때 그림 자리를 찾는다(P-027)
7. `## 머리말·꼬리말`, `## 각주·미주`, `## 메모` — 메모가 붙은 글자와 메모 내용. 실측 템플릿 10종의 메모는 이전 과제 문서의
   **검토 의견**(확인 요청·수정 표시·담당 지정)이었다 — 작성 안내로 단정하지 말고 내용으로 판단한다

표 격자:

```
#### 표 `s0.t1` — 3×3 · 캡션: 표 3. 일정 · 격자 OK
| r\c | c0 | c1 | c2 |
| r0 | 가<br>나 ⟨병합 1×2⟩ | ◀ | 다 ⟦필드 담당자⟧ |
| r1 | 라 | 마 | 바<br>사 ⟨병합 2×1⟩ |
| r2 | 아 | 자 | ▲ |
```

- 병합 셀은 왼쪽 위 칸에 글자와 `⟨병합 행×열⟩`, 가려진 칸은 `◀`(가로)·`▲`(세로)
- 셀 안 여러 문단·줄바꿈은 `<br>`. 셀 안 중첩 표는 그 칸에 `[표 s0.t1.r2c0.t0]`로 자리만 표시하고 바로 아래에 따로 그린다
  (이 자리표시는 .md 그림에만 있다 — 모델의 셀 `text`·검색·바꾸기 건수에는 셀 자신의 글자만 들어간다)
- 글상자 안의 표도 같은 방식으로 따로 그린다(`tables` 명령도 포함)
- 셀 4,000칸이 넘는 표는 격자 대신 셀 목록

## 위치 ID

| 형식 | 가리키는 것 |
|---|---|
| `s0.p12` | 구역 0의 12번째 최상위 문단 (빈 문단도 번호를 먹는다) |
| `s0.t3` | 구역 0의 3번째 최상위 표 |
| `s0.t3.r2c1` | 그 표의 2행 1열 셀 (병합 셀은 왼쪽 위 칸 주소) |
| `s0.t3.r2c1.t0` | 그 셀 안 첫 번째 중첩 표 |
| `s0.hd0` `s0.ft0` | 머리말·꼬리말 |
| `s0.fn0` `s0.en0` | 각주·미주 |
| `s0.m0` | 메모 |
| `…x0` `…c0` `…o0` | 글상자, (표 아닌 개체의) 캡션, 모르는 개체 |

같은 문서를 다시 읽으면 같은 ID가 나온다. 목표 2·3에서 "어느 칸"을 주고받을 때 이 ID를 쓴다.

## 경고를 만나면

- `파싱 누락 의심 {'P': (파싱 수, 원문 수)}` — 한/글이 준 XML에 이 스킬이 모르는 배치가 있다. 결과에 빠진 글이 있을 수 있으니
  사용자에게 알리고 `tools/hwpx-drm/dev/capture_hwpml.py --skip-synthetic --vocab <파일>`로 구조(이름·개수만)를 채취해 보고한다.
- `모르는 개체 안 문단 {'TAG': n}` — 글은 `기타 개체` 블록으로 살렸다. 위치가 중요하면 보고.
- `격자 불일치` — 병합 정보가 행×열을 정확히 덮지 않는다. 그 표의 셀 위치를 그대로 믿지 말고 셀 목록으로 확인.

## 사각지대

- **제목(개요) 기준 두 가지** — (1) 문단 모양이 '개요'인 문단(`level_src: outline`, 실측 10종 중 8종). (2) 그런 문단이 하나도 없는
  문서는 `1.1 적용범위`처럼 번호로 시작하는 짧은 최상위 문단(`level_src: number`, 수준 = 번호 마디 수; 실측 SDP·시험평가 계획서).
  (2)는 추정이다 — '12.5 kg 이상' 같은 짧은 숫자 문단도 제목으로 잡힐 수 있다. .md 의 `## 개요` 머리에 어느 기준인지 적힌다
- **개요 번호**(1., 1.1.)는 한/글이 자동으로 붙이는 번호라 (1)의 글자에 없다. 계산해서 붙이지 않는다 — 실측에서 수준 순서로 센 번호가
  문서 안 목차와 어긋나는 문서가 많았다(목차 미갱신·수준 건너뜀, `logs/P-017_evidence/outline_toc_check.md`). 번호가 필요하면 목차 문단을 본다
- 쪽 번호·자동 번호(그림·표 번호는 캡션 안에서 숫자로 들어감)
- 그림·도형 자체(그림 데이터는 읽지 않는다). 글상자·캡션의 글자만
- 변경 추적·숨은 설명

## 파이썬 API (목표 3 작성 스킬용)

```python
import sys; sys.path.insert(0, r"<스킬 폴더>\scripts")
from hwpx_api import HwpxSession
import hwpml_parse as hp
with HwpxSession(timeout=180) as s:
    s.open(r"C:\...\문서.hwpx")
    m = s.model()                       # dict: stats, fields, body, headers, footers, footnotes, memos ...
    for loc, kind, text in hp.iter_locations(m): ...
    t = hp.find_table(m, "s0.t3")
```

모델의 `body` 블록: `{"type":"para","id","text","style","align","level"?,"marks"?,"heights"?}`, `{"type":"table","id","rows","cols","caption","grid_ok","cells":[{"id","row","col","rowspan","colspan","text","field"?,"header"?,"tables"?}]}`,
`{"type":"textbox"|"caption"|"other","id","owner","text"}`.
- `marks`: 문단 안 글자가 아닌 개체의 자리 `[[글자 위치, 태그], …]`(구역 정의·머리말·쪽 번호 위치·책갈피·표·필드·제목 차례 표시 등) — 캐럿으로 글자를 지울 때 개체를 피하는 근거(P-025). 개체 없는 문단에는 키가 없다
- `heights`: 문단 글자 크기(HWPUNIT, 1100 = 11pt) 목록 — 글자가 있는 TEXT 의 글자 모양 크기, 작은 것부터. 본문 글자 크기를 맞췄는지 확인하는 근거(P-031). 글자 모양 목록(CHARSHAPE)을 못 찾으면 키가 없다
- `ctrls`: 문단 TEXT 안의 조판 개체 `{"at","tag","attrs","offset","children"}` (offset = 그 개체 앞 글자 수), `styledefs`·`numberings`: 스타일 정의·번호 모양
- `styledefs[].char.langs`: 글자 모양의 언어별 값 `{언어: {"font","type","ratio","spacing","relsize"}}` — 언어는 `hangul`·`latin`·`hanja`·`japanese`·`other`·`symbol`·`user`, `type` 은 글꼴 종류(`ttf`·`hft`). HWPML 에 있는 언어·값만 담는다(P-045, 문서 작성기 칸 너비 재기). `hangul`·`latin`·`ratio`·`spacing` 키(한글 값)는 그대로 있다
- `headers`·`footers`: `{"id","text","apply","page_number"?}` — `page_number: true` = 쪽 번호 필드(AUTONUM Page)가 든 머리말·꼬리말
