# doc-writer — 내용 명세(.md) → DocuRay 한/글 산출물

정본은 이 파일 `tools/doc-writer/SKILL.md` 다. 배포 사본 `.claude/skills/doc-writer/SKILL.md` 는 사용자가 `tools/test_hwpx/20.deploy_doc_writer.bat`
으로 만든다(`.claude` 는 원격으로 쓸 수 없다, D-007). 작성기는 `tools/doc-writer/write_doc.py` 이고 **명세 문법·검사 목록의 단일 원본은 그 파일
머리말**이다 — 여기에는 요점만 둔다. 첫 적용은 SUM(`output_docs/SUM/SUM_spec.md` → `SUM_사용자지침서.hwpx`, P-027~P-051)이다.

## 0. 언제 쓰나 · 세션 환경

- 쓴다: 과제 산출물을 새로 쓰거나 고쳐 다시 쓸 때, 출처 문서 내용을 산출물에 옮길 때, 작성기 보고를 읽을 때.
- 안 쓴다: DRM 문서 하나를 읽기만 하거나 필드만 채울 때(`hwpx-drm`), 템플릿을 만들 때(`tools/doc-templates`).
- 사용자가 손본 문서(목차·그림·표를 한/글에서 고친 판)에 절을 **더할** 때는 명세로 다시 쓰지 않는다(손본 것을 잃는다) —
  `tools/doc-writer/insert_doc.py`(§4-1, 브리지 `insert` 연산)로 그 문서에 끼워 넣는다.

| 세션 | 출처·참고본 읽기 | 쓰기(`write_doc.py`) |
|---|---|---|
| Windows (Claude Code, 한/글 있음) | `hwpx-drm` 직접 | 직접 실행 — 한/글 창을 모두 닫고 |
| Linux (Cowork, `device_bash` 포함) | **office-drm-bridge** — 수락 계약, 워커는 **drmHWP 저장소의** `run_bridge_worker.bat` 으로 켠다(워커 첫 줄 `root=` 가 drmHWP 인지 확인 — PROJECT_RULES §2, D-055) | 단계 bat 을 만들어 **사용자가 실행** |

Linux 에서 DRM 파일은 암호문으로 보인다. 복호화하지 않는다. 브리지 세부는 `.claude/skills/office-drm-bridge/references/session_environment.md`.

## 1. 작업 순서

1. **근거** — 표준서식 목차·작성목적은 별첨1-2 덤프 `logs/P-022_evidence/form_dumps/별첨1-2. 기술문서 작성서식.dump.md`, 검토 기준은
   매뉴얼 본문 `reference/dapa_manual/md/`. 장은 표준 목차 그대로 둔다 — 더할 것은 그 장 안의 절로, 부록 성격이면 '참고사항/부록' 장에
   (D-025·D-035·D-056).
2. **출처 읽기** — 평문 HWPX 는 hwpx-drm `inspect`. DRM 은 브리지 `inspect`: 계획(문서·연산·이유·평문 산출물·지우는 때)을 제안하고
   수락받은 뒤 보낸다. 평문 .md 는 `bridge/quarantine/<id>_md/` 안에서만 읽고 명세에 반영한 뒤 `purge`. 판독은 원본과 같은 등급이다.
   - 그림: 평문 출처는 `tools/doc-writer/extract_figures.py`, **DRM 출처는 `hwpx_drm.py images`(브리지 `images`)** 로 꺼낸다 —
     평문 그림 파일(보안담당자 허락, D-062 — D-028 의 'DRM 출처 그림은 꺼내지 않는다' 대체). 꺼낸 그림은 원본과 같은 보안 등급.
     손본 문서에 넣을 때는 꺼내지 않고 한/글 안에서 옮기는 길도 있다(§4-1 `hwpx:` 그림·`figure_pack.py`). 사용자 사진에서 누를 곳은
     머스타드 박스(#E1AD01)로 표시한다(D-033).
3. **명세** — `output_docs/<약어>/<약어>_spec.md`. 시작점은 `tools/doc-writer/samples/new_doc_spec.md`(§2 서식이 들어 있다).
   출처 문장은 뜻을 바꾸지 않고(오타·표기만), 출처에 없는 것은 `> 작성 필요` 메모로 남긴다(D-025·D-027). 출처에서 되풀이되는
   절차는 한 곳에 두고 `{{절:제목}}` 으로 가리킨다(P-051) — 작성기가 명세 제목 차례로 센 '번호 제목'으로 바꾸므로 앞에 절이
   늘어도 따라가고, 인용한 제목을 바꾸거나 지우면 명세 오류다. 단계는 바로 뒤에 `{{절:모의 시작}} 2)~8)` 처럼 쓴다(그 절 단계
   수와 대조 — `2)-8)`·`2)부터 8)까지`·`{{절:…}}의 2)~8)`, 나열 `2)·7)·8)`·`1), 2), 9)`·`2) 및 9)` 도 읽고 나열은 원소마다 본다.
   '4)에서 2)로' 의 '에서' 는 범위가 아니다 — 범위는 `~`·`-`·`부터` 로 쓴다). 출처의 절 번호(다른 문서의 번호)는 옮겨 쓰지
   않는다 — 꼭 써야 하면 `{{글자:체계사양서 1.1 적용범위}}` 처럼 글자 그대로 두고, 그 문서의 단계는 바로 뒤에 붙인다
   (`{{글자:…}}의 2)~5)` — 검사 밖. 이 문서 절과 번호·제목이 같으면 고칠 것으로 잡히기 때문). 저장소의 모든 명세(`output_docs/*/*_spec.md`)는 단위 시험이 인용 오류·`text_checks` 고칠 것 0을 지킨다(D-058) —
   작성기에서는 경고지만 저장소 명세는 고쳐 써야 시험이 통과하고, 다른 문서 초안 하나가 어긋나도 모든 단계 bat 의 [U3] 이 멈춘다
   (의도 — 초안을 고치거나 잠시 `output_docs` 밖에 둔다). 의심(이 문서에 있는 절 번호 뒤 글이 그 절 제목이 아닌 곳 — '화면은
   1.2 초 간격'처럼 보통 글일 수 있다, 이 문서에 없는 '3.1.1항', 낱말일 수 있는 '1.1절차', 인용 뒤에 떨어진 범위, 캡션 안 번호)은
   단위 시험을 막지 않는 경고다 — 읽어 보고 절 인용이면 고치고, 아니면 `{{글자:…}}` 로 감싸 둔다
   (`화면은 {{글자:1.2 초}} 간격` — 가짜 쓰기·실측 bat 기대는 경고 0이라 그대로 두면 거기서 멈춘다. 캡션 안이면 캡션 글을 바꾼다).
   명세 머리말 목록에 요청마다 무엇을 어디서 옮겼는지 한 줄씩 남긴다.
4. **검토서·승인** — `review_docs/YYMMDD_HHMM_*.md`: 출처 → 절 대응, 고친 것, 남긴 작성 필요, 판단 근거. 승인 뒤에만 산출물을
   만든다(GLOBAL Rule 1).
5. **가짜 COM 시험** — `python -m unittest discover -s tools/doc-writer/tests` 와 명세 전체를 가짜 한/글로 끝까지 쓰기
   `python tools/doc-writer/fake_write.py <명세.md> <결과.json> [--dummy]` — `all_ok`·끝 코드로 판정(어느 명세에나 맞는 판정과
   음성 대조 fail-closed, 경고 0 — 실측 bat 기대와 같다). 그림 파일이 없는 사본이면 `--dummy`, SUM 꼴(그림 있음·캡션 없는 표 없음)이면
   `--sum-negative-control` 로 17.sum_step7 실측 꼴 기대를 더한다. 흉내는 **공통 템플릿만** 본뜬다(다른 템플릿이면
   `template_modeled` 거짓), 명세 경로는 **저장소 안 상대 경로만** 받는다(절대 경로·드라이브·'..' 이면 아무것도 쓰지 않고 끝 코드 2 —
   저장소 밖 그림은 저장소 안으로 복사해 가리킨다). 명세 오류(없는 `{{절:}}` 인용·저장소 밖 out·출력이 템플릿·없는 명세나 표 서식
   파일·UTF-8 이 아닌 명세·키 값 안의 다른 키)도 끝 코드 2 + 결과 JSON `error` — 끝 코드 1 은 판정 FAIL 이다(결과 JSON 이
   all_ok false 에 '실행 중' 이면 흉내가 멈춘 것 — 콘솔 traceback 을 본다). 결과 자리(.json)에 파일이 있으면 지난 가짜 쓰기 결과(표지
   `"tool": "doc-writer/fake_write"`)일 때만 덮는다 — 명세·템플릿·표 서식·실측 판정 JSON(`step8_check.json` 처럼 all_ok 가 있어도)을 결과
   자리로 주면 아무것도 쓰지 않고 끝 코드 2(결과 폴더가 없어도 2). 표지 없는 지난 판(7회차 앞) 결과·빈·잘린 결과도 지난 결과로 보지 않는다
   (fail-closed — 지우거나 다른 경로를 준다). 음성 대조 `negative_controls.py` 도 같은 표지 규칙(표지 `negative_controls` — 결과 폴더가
   없으면 traceback·끝 코드 1). 결과 JSON 은 시작할 때
   all_ok(음성 대조는 all_caught) false 로 덮으므로 중간에 멈춰도 지난 통과가 남지 않는다. 칸 안 여백 판정은 흉내 칸 글자가 늘 10pt 라 500 고정이다 — 글자 크기에 따른
   규칙은 단위 시험이 본다.
6. **단계 bat** — §5 꼴로 `tools/test_hwpx/NN.<약어>_stepK.bat` 를 만들고 사용자가 실행한다.
7. **보고 판독** — §6. FAIL 이면 저장되지 않았다(지난 판 그대로). 원인은 보고의 오류 줄·`check` 에 있다.
8. **기록** — 보고 사본을 `logs/P-xxx_evidence/` 로 옮겨 둔다(다음 실행이 덮어쓴다). 원장(F-/D-)·PROJECT_RULES §2·로그·같은 날
   검토를 남긴다(GLOBAL Rule 4·8·11·15).

## 3. 명세 요점 (상세는 `write_doc.py` 머리말)

````
```json 머리  template · out(.hwpx) · keys {"{{키}}": 값 | [자리별 값]} · front {"양식 글자": 값} · table_style
              · styles {자리: 템플릿 스타일 이름} — 보통 쓰지 않는다(기본 = 공통 템플릿). heading 은 '… {level}'(수준 1~7 마다
                다른 이름 — 한 수준만 쓰는 명세도 '{level}' 자리를 둔다), 그 밖의 자리 para·item·need·caption·th·td·anchor·figure
# … #######               제목 → COMSAF 개요 1~7 (번호는 글자로 쓰지 않는다 — 한/글 개요 자동 번호)
일반 줄                     본문 문단
- 항목 / 두 칸 들여 - 항목    ○ 항목 / - 항목
표: 제목 + | … | 표          표 + 위 캡션 '표 N 제목' (칸 안 <br> = 칸 안 문단). '표:' 줄이 없으면 캡션 없는 표
![제목](그림 "가로x세로")     그림 + 아래 캡션 '그림 N 제목' (파일이 없으면 자리 표시 그림 + '그림 삽입 필요' 메모)
> 내용                      ※ 작성 필요: 내용 (보고 '추가 내용 필요'에 모인다 — 채운 뒤 지운다, D-016)
<!-- … -->                 명세 메모(문서에 넣지 않음)
{{그림:캡션}} · {{표:캡션}}   그 캡션의 번호 — 본문·항목·메모·표 칸 안. 없는 캡션·같은 캡션 둘은 명세 오류
{{절:제목}} 2)~8)            그 절의 '번호 제목'(+ 단계) — 없는 제목·같은 제목 둘·수준 건너뛴 제목은 명세 오류, 단계는 그 절
                            바로 아래 'N) …' 줄 수와 대조(경고 — 이음 ~·∼·-·부터, 나열 가운뎃점·쉼표·및·와·과, 조사 '의'). 인용에 붙지
                            않은 'a)~b)' 는 단계 줄이 있는 절의 문단·항목에서 그 절 단계와 대조. 제목·캡션 안에는 {{…}} 를 쓰지 않는다
{{글자:…}}                   그 글자 그대로(검사 밖) — 이 문서 절과 번호·제목이 같은 다른 문서 절('체계사양서 1.1 적용범위')·
                            의심을 받은 보통 글('1.2 초'). 바로 뒤 단계('{{글자:…}}의 2)~5)')도 보지 않는다
````

- 첫 제목은 템플릿 첫 장 제목('개요')과 같아야 하고, 템플릿 본문은 그 제목 하나뿐이어야 한다. 그래서 양식 안내 상자가 든 문서별 템플릿
  (`output_docs/templates/SW기술문서-0N_*.hwpx`)은 작성기가 받지 않는다 — `write_doc.py` 의 거절 글:
  `"첫 장 제목 뒤에 표·개체가 있다 %s — 본문을 비운 템플릿이어야 한다"`.
  그 템플릿의 판독 `output_docs/templates/md/<약어>.md`(DRM 평문 등급)는 목차·작성 안내 참고로만 쓴다.
- 번호 뒤 조사는 피한다('표 15과' 문제) — `…값({{표:캡션}})은` 처럼 괄호에 넣는다. 절 인용 뒤 조사는 제목 끝 글자에 맞춘다
  (`{{절:모의 시작}}으로`·`{{절:모의 종료}}로`).
- 같은 제목의 절이 둘이면 `{{절:}}` 로 가리킬 수 없다 — 인용할 절은 제목을 다르게 짓는다. 제목 수준은 건너뛰지 않는다('#' 다음 '###').
- 한 문단에 `1) {{절:가 절}} 2) {{절:나 절}}`·`… 2) {{글자:…}}` 처럼 인용을 나열하면 번호는 단계로 보지 않는다(인용 뒤 번호 하나
  다음이 또 절·글자 인용 — 조사 '의' 로 이은 `{{절:가 절}}의 9) {{글자:…}}` 는 가 절 단계다). `1) {{절:가 절}} 2) 화면 확인` 처럼
  다음 항목이 글이면 '2)' 를 가 절 단계로 읽는다 — 나열이면 인용 뒤에 쉼표를 둔다(`{{절:가 절}}, 2) 화면 확인`). 나열 기호는
  쉼표·가운뎃점(·・ㆍ)·및·와·과다('또는'·'그리고'·'혹은'·'/'·'‧' 는 아니다 — 첫 단계만 본다). 범위는 '~'·'-'·'부터' 로 쓴다('내지' 는 첫 단계만 — D7-①-N01). 문단 머리 목록 번호 '1. …' 도 절 인용으로 보지 않는다.
- 단계 줄은 번호 뒤에 빈칸을 둔 '1) …' 문단·항목이다 — '1)설치'·'4)와 5)는'·'3)의 결과' 처럼 빈칸 없는 문단 머리, 범위 머리
  '2) ~ 5)는', 띄어 쓴 나열·조사 머리 '4) 및 5)는'·'4) 또는 5)는'·'3) 의 결과'·'4) 에서 2)로' 는 단계 줄이 아니다. 그 밖의 꼴
  ('4) 혹은 5)는'·'4) 내지 5)는'·'4) 는 …')은 단계 줄로 센다 — **단계를 가리키는 문장은 단계 번호로 시작하지 않는다**(`단계 4)·5)는 …`). 단계를 끼우면 뒤 번호를 다시 매긴다 — 매기지 않은 끼움('1)' 이 둘)은 단계 수(가장 큰 번호)가
  그대로라 범위 고정 시험도 알리지 못한다.

## 4. 작성기가 지키는 것 (쓴 뒤 HWPML 대조 — 어긋나면 저장하지 않는다)

- 앞부분(표지·이력서·목차·머리말·꼬리말)은 키 바꾸기 말고 그대로
- 붙인 블록의 글자·스타일·표 칸 글자, 최상위 문단 수(템플릿 + 블록), 그림 수
- 표·그림 캡션 글자(자동 번호 포함)·캡션 스타일 = 명세, 계획에 없는 '새 번호로 시작' 조판이 없음
- 본문 첫 쪽 인쇄 번호가 쓰기 전과 같음(두 길로 읽는다 — 못 읽으면 경고)
- 제목마다 한/글 개요 번호(GetHeadingString)의 숫자 = 명세 제목 차례로 센 번호 — `{{절:}}` 인용에 쓴 번호(못 읽으면 경고, U-32).
  `{{절:}}` 인용이 없는 명세는 숫자만 다르거나 번호 꼴이 숫자가 아니면('가.'·'①') 경고만 하고 저장한다(문서 글자는 맞다). 제목
  수가 다르거나 번호 없는 제목(''·글머리표 '•' 처럼 번호 꼴 글자가 없음)이면 인용과 관계없이 저장하지 않는다(쓴 문서가 틀렸다 —
  거절 글에 그 항목이 먼저). 다 읽은 뒤
  캐럿은 본문 첫 장 제목으로 돌린다
- DocuRay 보호로 저장(평문이면 종료코드 3, 반출 금지), 다시 열기 OK, 템플릿 원본 불변
- 경고만 하는 것: 표 서식(선·배경·제목 셀·안 여백·너비) 대조, 글자 크기·문단 정렬, 계획한 새 번호를 못 찾음, 쪽·개요 번호를
  못 읽음, 쓰기 전 명세 검사 `text_checks` — 고칠 것(단계 범위·나열이 그 절 단계 밖, 글자로 쓴 절 번호(맞아도)·'4.3.4.1절에'·
  '제3장의', 인용 밖 '표 N'·'표N'·'그림 2가' — 숫자에 붙은 세는 말 '표 3개'·'그림 2장'·'표 3가지' 빼고, 제목 수준 건너뜀)과
  의심(점 든 번호가 이 문서 절 번호인데 뒤 글이 그 절 제목이 아님 — '1.2 초' 같은 보통 글일 수 있다, 이 문서에 없는 'N.N절/항'·
  '제N장', 낱말일 수 있는 '1.1절차'·'제3장비', 인용 뒤에 떨어진 범위, 캡션 안 글자 번호). 보고 JSON
  `text_check.ranges` 에 범위 인용이 모두 있다(인용에 붙지 않은 범위는 `by: local`) — 절에 단계를 더하면 범위 끝이 낡을 수
  있으니 SUM 처럼 시험에 고정한다(`test_sum_step_ranges_pinned`, 16곳)

## 4-1. 기존 문서에 끼워 넣기 — `insert_doc.py` (P-052)

- `python tools\doc-writer\insert_doc.py <대상.hwpx> --spec <블록 명세.md> --before <제목 글자> --out <새 파일.hwpx>` —
  Linux 세션은 브리지 `insert`(spec·before·out). 문법·대조는 그 파일 머리말: 제목(`#` 수 = 개요 수준)·문단·항목·그림
  `![캡션](hwpx:출처.hwpx#k "가로x세로")`(DRM 출처의 k 번째 그림을 한/글 안에서 옮김 — 평문 파일이 생기지 않는다). 표·그림 파일·
  작성 필요·`{{…}}` 인용은 쓰지 않는다.
- 대상은 열기만 하고 결과는 늘 새 파일. 넣은 곳 밖·표 칸·머리말·새 번호 조판·기존 스타일 정의·캡션 차례·제목 개요 번호가 어긋나면
  저장하지 않는다. 경고: 출처 문서 스타일이 더해짐(PoC '개요 2'), 번호가 바뀐 제목, 새 그림 번호 이상을 가리키는 본문 글자 '그림 N'
  (목차 줄 포함) — 글자 번호는 브리지 `search`→`replace`(괄호까지 넣어 찾기)로 고친다. 목차는 사용자가 다시 만든다.
- 실측: PoC `tools/test_hwpx/21.p052_insert_poc.bat`(`logs/P-052_evidence/insert_poc_report.md`).
- 큰 출처(그림 여러 장)는 먼저 **그림 꾸러미** `tools/doc-writer/figure_pack.py <출처> --out-dir <새 폴더> [--only 1,3]`(브리지 `figpack`) —
  출처를 한 번 열어 그림 문단만 남긴 `all.hwpx` 와 그림 하나짜리 `figKK.hwpx`(모두 DocuRay 보호 문서, 그림 파일로 꺼내지 않음)를 만들고,
  끼워 넣기 명세에서 `![캡션](hwpx:<폴더>/figKK.hwpx#1)` 로 쓴다 — 그림마다 출처 전체를 끼웠다 지우지 않는다. 보고에 k·캡션 제목·크기.

```bat

echo W_EXIT=%ERRORLEVEL%
exit /b 0
:fail
echo unit tests failed - nothing was run with Hwp

```

  `if errorlevel 1 goto :copyfail` — `logs/P-051_evidence/bat_copy_once_check.py` 로 확인).

## 9. 새 산출물 시작 체크리스트

1. 표준서식 번호·작성목적·표준 목차를 덤프에서 확인하고, 검토 기준(매뉴얼 본문)의 그 문서 항목을 읽는다.
2. `samples/new_doc_spec.md` 를 `output_docs/<약어>/<약어>_spec.md` 로 복사 → out·keys·front 값 → 목차대로 제목.
3. 출처 판독 → 절 대응 → 검토서 → 승인.
4. 명세 본문 → 가짜 COM 전체 쓰기(§1-5, `fake_write.py`) → 단계 bat → 사용자 실행 → 보고 판독 → 기록.
5. 문서별로 처음 쓰는 표 캡션이 표 서식 파일에 없으면 '용어/약어 설명' 꼴이 된다 — 다른 꼴이 필요하면 alias 를 더한다(D-042).
6. 공통 템플릿이 아닌 템플릿의 첫 문서는 첫 실측 보고 `check.headings.samples` 로 수준마다 개요 번호 꼴을 본다 — 작성기는 번호 꼴
   글자(글자·숫자)가 없는 꼴('□'·'○'·'•'·'')을 번호 없는 제목(저장 거절)으로, 원 문자 '㉮'·'Ⓐ' 도 지금은 번호 없음으로 본다. 거꾸로
   글머리표로 쓰는 'o'·'ㅇ'·'v' 는 번호 꼴 글자로 받아 인용이 없으면 경고·저장한다(U-32 — 그런 꼴의 템플릿이면 셈을 고친다, D7F-N03).
   제목·캡션 스타일 이름을 바꾼 명세(styles)면 보고 '추가 내용 필요' 의 절 칸이 '(첫 장)' 으로 나오고(제목을 'COMSAF' 머리 글자로
