## 1. 변경 파일 (전 8건, `.claude/skills/` 하위)

### uf-designer (D1)

**scripts/validate_uf_design.py** (수정)
- 성공 메시지 카운트: `re.findall(r"UF-\d{2}-\d{2}")`(요약표·상호참조까지 세는 오보의 원인) → `^- UF-ID:` 멀티라인 기준.

  헤더 "UF N개" 선언 / 요약표 행 수(`| UF-##-## |`) / 본문 블록 수 / 소유자 분포 선언("UF-local a / guard-rail+chain b / IF-acceptance c") vs `Ownership:` 실카운트.

**SKILL.md** (수정) — Quality Checklist에 2항 추가: tally 일치 조건, **증보 모드**(기존 uf.md에 UF 추가/삭제 시 헤더·요약표·분포 재계산 + Phase C~E 재실행 의무).

### uf-chain-validator (D2·D4·D5)

**SKILL.md** (수정)
- frontmatter `allowed-tools: Read, Write` → `Read, Write, Bash, Grep, Glob` — 교차 대조를 기계적으로 수행할 수단 부여(도구 봉인 해제).
- Inputs에 `rd/requirements.md` 편입 — REQ 블록 Tests/Evidence 선언도 Gate 2 대조 범위.

- Gate 2: 기계화 필수 지시 — 판정 전 validate_test_paths.py 실행, 검사는 반드시 **선언→실물** 방향(실물 목록→존재 확인 역방향 금지 — 과거 오판의 원인), `::함수` 단위 대조, GHOST_FUNC=즉시 FAIL. FAIL 조건 추가: 선언 역할이 다른 실물로 이행 구현된 경우 문서 갱신 전까지 FAIL.
- Gate 3: 신선도 "7일 경과 WARN" 폐지 → "evidence commit_sha ≠ HEAD + src/include/tests diff 존재 = STALE, 인용 금지"(STALE 근거 PASS 주장 = FAIL). commit_sha 미기록은 WARN.
- Bundled Scripts 절 신설.

**scripts/validate_test_paths.py** (신설, Gate 2 기계화)
- 대상: rd/uf.md, rd/requirements.md, rd/uf_split/*.md (선언의 원천만 — 사료성 리뷰 문서 제외).
- 추출: `tests/…`·`scripts/…` 확장자 있는 경로 토큰, `<file>.(py|cpp)::<func>` 토큰.
- 판정 버킷: `OK` / `PLANNED`(선언 라인에 '예정' 마커 — 미구현 계획 명시) / `MISSING`(파일 없음 — 리포트, `--strict` 시 FAIL) / `GHOST_FUNC`(파일은 있는데 함수 없음 — **항상 FAIL**, '거짓 선언').

## 2. 재현 명령 (기대값 병기 — 저장소 루트에서)

```bash
# (1) D1 검증기 — 기대: exit 0, "55 UF blocks validated; header/table/ownership tallies consistent"
python3 .claude/skills/uf-designer/scripts/validate_uf_design.py rd/uf.md

# (2) D5 게이트 — 기대: exit 0, "[IF-01.state] OK — 계약 6필드 전부 include/hfsim/types.hpp::State에 존재"
python3 .claude/skills/uf-chain-validator/scripts/validate_contract_fields.py .

# (3) D2 게이트 — 기대: exit 0, "OK 28 / PLANNED 4 / MISSING 321 / GHOST_FUNC 0"
#     PLANNED 4 = M4 예정 마커 2건×(uf.md+uf_split). MISSING 321 = 미착수 M1~M4 계획 pytest 계층(리포트 전용).
python3 .claude/skills/uf-chain-validator/scripts/validate_test_paths.py --root .

# (4) 음성 대조(검출력 확인, 선택): rd/uf.md 헤더의 "55"를 임의로 "50"으로 바꾸면 (1)이 [tally] FAIL로 떨어져야 한다. 확인 후 원복.
```

## 3. 권장 리뷰 관점

1. **GHOST_FUNC 엄격성 vs '예정' 마커 규약**: 계획 선언은 '예정' 문자열로만 식별한다 — 마커 누락·오타 시 오탐(FAIL)하는 보수적 설계가 적정한지, 마일스톤 태그(M4 등) 연동이 더 나은지.
2. **MISSING 321건의 승격 시점**: 현재 리포트 전용. 어느 이벤트(M1 착수, IF 완료 선언)에서 `--strict`/FAIL로 승격할지 게이트 정책 결정 필요.
3. **도구 봉인 해제의 부작용**: uf-chain-validator에 Bash를 허용한 것이 스킬 권한 원칙과 충돌하지 않는지(검증 전용 스크립트 실행 용도로 한정됨).
4. **tally 정규식 견고성**: 헤더 "UF N개"·분포 선언의 표기가 바뀌면 검사가 조용히 스킵된다(있을 때만 검사) — 필수화할지.
5. **수명주기 강제력**: eval-runner 수명주기는 지시문+check#8 조합이다. runs.yaml의 MANUAL_PENDING 해소를 스크립트로 교차 검사하는 후속(validate_eval_report가 runs.yaml도 읽기)이 필요한지.
6. **잔존 표류(범위 밖 기록)**: uf-designer SKILL.md v2 표기 ↔ validate_uf_design.py 구형식 검사 간 표류는 비파괴적이라 미수정 — 후속 정리 후보.

## 판단 근거

- 개선을 "새 스킬 신설" 대신 기존 스킬에 스크립트 2개+지시 수 줄로 한정한 근거: 결함 5종이 모두 기존 게이트의 사각(버그/공백/기준결함)이므로 게이트 보강이 신설보다 비용·효과 우월(GLOBAL_RULES Simplicity First).
- 신설 게이트의 실효 증거: validate_test_paths 첫 실행이 기존 감사가 놓친 결함 2건(M4 계획 UF의 미표기 선언)을 즉시 적발 — "지시문이 아니라 기계화가 해법"이라는 원인 분석의 실증.
