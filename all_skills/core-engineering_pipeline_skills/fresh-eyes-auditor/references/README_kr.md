# fresh-eyes-auditor — 한국어 사용 가이드

## 왜 필요한가

작업을 만든 에이전트에게 "검토해줘"라고 하면, 자기 결론을 다시 확인하는 확증 편향이
작동한다. 이 스킬은 **대화 맥락이 전혀 없는 새 에이전트**를 만들어 파일만 주고
감사시킨다 — 파일에 적히지 않은 것은 그 에이전트에게 존재하지 않으므로,
"문서만 보고도 이해되는가"가 자동으로 함께 검증된다.

## 무엇을 잡는가 (4축)

| 축 | 예 |
|---|---|
| 모호함 | 수치 없는 수락 기준, 미정의 단위·좌표계, "적절히" 류 |
| 억지 | 근거 없는 비약, 판단 근거 없는 결정, 순환 논증 |
| 오류 | 차원 오류, 문서 간 수치 불일치, 설계↔코드 계약 불일치, 깨진 참조 |
| 환각 | 없는 논문·식 번호 인용, 존재하지 않는 API, 출처 없는 수치 (웹 대조) |

## 동작 방식

1. **범위 확정**: 설계 문서(rd/)가 있으면 ①문서 자체 + ②설계↔코드 비교,
   없으면 코드만. 사용자 지정 시 그것만.
2. **무맥락 스폰**: 새 에이전트에게 파일 경로+루브릭+출력 형식만 전달.
   세션 요약·의도 설명은 오염이므로 금지.
3. **트리아지**: 발견마다 인용 실재 확인 → 파일 내 해명 대조 → 실질성 판정.
   검증자 자신의 환각(MISQUOTE)도 여기서 걸러 기록한다.
4. **자문 리포트**: `review_docs/`에 채택/기각/판정불가 + 후속 라우팅.
   파이프라인을 차단하지 않는다 (자문 전용).

## 사용법

```
/fresh-eyes-auditor
지금까지 설계/구현에 모호함, 억지, 오류, 환각이 없는지 검토해줘.
(선택) 범위: rd/ + src/uf/     (선택) 웹 검증: 기본(출처·수치 한정)
```

## 다른 검증 스킬과의 경계

- `uf-chain-validator`: 계약·테스트·증적의 **기계적** 정합 (3-Gate)
- `code-reviewer`: 코드 품질 **3-렌즈** 리뷰 (외부 코딩 에이전트 구현물)
- `fresh-eyes-auditor`: **인식론적** 감사 (모호함·억지·오류·환각) — 무맥락 에이전트가 수행

셋은 대체가 아니라 보완 관계다. 큰 마일스톤(설계 확정 직후, 통합 완료 직후,
제안서 제출 직전)마다 이 스킬을 한 번 돌리는 것을 권장한다.

## 한계 (알고 쓰기)

- fresh agent도 LLM이다 — 오탐이 있으며, 트리아지가 이를 걸러낸다 (기각 기록 포함).
- 파일에 없는 배경지식이 필요한 결함(예: 조직 내부 관례 위반)은 UNVERIFIABLE로 뜬다.
- 자문 전용이므로 강제력이 없다 — 게이트가 필요하면 사용자가 G7로 승격 지시.
