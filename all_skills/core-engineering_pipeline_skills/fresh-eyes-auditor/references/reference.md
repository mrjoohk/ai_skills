## 2. 4축 루브릭 상세

### 모호함 (Ambiguity)
- 수치 없는 수락 기준 ("빠르게", "충분히", "적절히", "높은 정확도")
- 다의적 용어가 문서 간 다른 의미로 사용 (동일 심볼·용어의 정의 충돌)
- 미정의 단위·좌표계·범위·타입 (I/O Contract의 "tensor", "data" 류)
- 책임 소재 불명 ("처리한다"의 주어 없음, Verification Owner 미선언)
- 경계조건 미정 (빈 입력·최대값·실패 시 동작이 규정되지 않음)

### 억지 (Forced logic)
- 근거 없는 비약 (전제→결론 사이 단계 생략)
- 결론 선행 (결정이 먼저 있고 근거가 사후 조립된 흔적 — 대안 비교 부재)
- 판단 근거 없는 결정 (선택지가 있었는데 사유 기록 없음)
- 과잉 일반화 (한 사례→전체 주장), 제약·가정과 모순되는 주장
- 순환 논증 (A의 근거가 B, B의 근거가 A)

### 오류 (Errors)
- 수식·단위·차원 오류 (LHS≠RHS 차원, 단위 환산 누락)
- 문서 간 수치 불일치 (같은 KPI/임계값/예산이 문서마다 다름)
- 논리 모순 (같은 문서 안에서 상충하는 두 진술)
- 깨진 참조 (존재하지 않는 파일·ID·섹션·식 번호 인용)
- [Mode A-2] 설계↔코드 불일치:
  - I/O Contract(타입·단위·형태·범위) vs 함수 시그니처·독스트링·실제 반환
  - Algorithm Summary vs 실제 구현 로직
  - 선언된 Edge Case vs 처리 코드·테스트 존재 여부
  - 선언된 Verification Plan 테스트 경로 vs 실제 테스트 파일
- [Mode B] 코드 내부: 가드 없는 경계, 죽은 분기, 계약 없는 암묵 변환

### 환각 (Hallucination)
- 출처 없는 사실 주장 (수치·성능·표준을 인용 없이 단정)
- 실재하지 않는 인용 (없는 논문·틀린 식 번호·없는 표준 규격) → 웹 대조 대상
- 존재하지 않는 API·라이브러리·함수 사용 (import 불가능한 모듈, 없는 메서드)
- 파일에 없는 내용을 "문서에 있다"고 참조 (깨진 내부 인용)
- 외부 수치 주장이 공개 값과 불일치 (물리 상수, 벤치마크 SOTA) → 웹 대조 대상

## 3. 트리아지 결정표 (본 에이전트)

| 순서 | 검사 | 방법 | 실패 시 분류 |
|---|---|---|---|
| ① | 인용 실재 | 해당 file:line을 직접 Read하여 인용문 대조 | REJECTED-MISQUOTE |
| ② | 기재된 해명 | 같은 파일·연관 파일의 판단 근거/가정 기록이 지적을 해명하는가 (해명 위치 인용 필수) | REJECTED-JUSTIFIED |
| ③ | 실질성 | 수정 시 산출물이 실제로 개선되는가 | REJECTED-TRIVIAL |
| — | 통과 | — | ACCEPTED |

- ②에서 세션 기억만으로 기각 금지 — 해명이 파일에 없으면 그것 자체가 "판단 근거 미기록"
  발견(억지 축)으로 전환하여 ACCEPTED 처리한다.
- 재실행 시: 이전 리포트와 대조해 ACCEPTED 발견에 `RECURRING`/`RESOLVED` 태그 부여.
