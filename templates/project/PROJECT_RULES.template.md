# PROJECT_RULES.md — <프로젝트명>

실제로 필요한 항목만 채운다. 없거나 모르는 값은 생략하거나 미확정으로 표시한다. 이 파일이 없다는 이유로 독립적인 작업을 중단하지 않는다.

## 목적과 환경

- 대상·목적: <사용자가 요청한 결과>
- 주요 입력·정본: <실제로 존재하는 파일과 역할>
- 실행 환경·검사: <발견한 실행기·관련 검사 명령, 해당할 때>
- 프로젝트 제약: <권한·기술·데이터·출력 요구사항>

## 작업 운영

- workflow_mode: lightweight
- lightweight: 현재 대화와 필요한 파일 중심으로 수행.
- tracked: [policies/TRACEABILITY.md](policies/TRACEABILITY.md)의 로그·대장을 이 프로젝트에서 사용. 기존에 필수인 추적 규약은 모드 이름이 없어도 유지한다.
- 태스크 분해: 작은 일은 메인 직접, 독립적으로 끝낼 수 있는 일은 명확한 입력·출력·수정 범위로 위임.
- 병렬 작업: 같은 파일의 writer는 하나. 공용 정본·로그·대장 병합은 메인 또는 지정된 단일 소유자.
- 출력 형식·위치: <사용자 지정 또는 기존 정본 위치; 없으면 필요한 시점에 정함>
- 필수 검사·승인 경계: <이 프로젝트에서 실제로 요구하는 것>

## 선택형 추적 설정

tracked 또는 기존 프로젝트 규약을 쓸 때만 채운다.

- 로그·대장·요청 ID 방식: <기존 방식 또는 번들 v2>
- 중요 불변식·검사 설정: <기계 검사와 수동 확인 대상을 구분>
- 증거 경로·기준선: <재현에 필요한 조건과 위치>
- 원년·이력 보존 규약: <필요할 때>
- 현재 미해결 사항: <확인된 제약과 후속 작업>

인증 정보는 환경 변수 이름이나 승인된 저장 위치만 기록한다. 실제 키 값은 이 파일에 넣지 않는다.
