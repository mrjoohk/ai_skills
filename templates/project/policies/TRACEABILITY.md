# 선택형 추적·검증 규약

PROJECT_RULES.md에서 workflow_mode: tracked를 선택하거나 기존 프로젝트가 로그·대장을 요구할 때 적용한다. 단순 질의·수정에 이 체계를 새로 설치하지 않는다. 기존 필수 승인·검증 주기·상태 의미론·스키마·식별자·보존 규약을 우선한다. 아래는 신규 추적 체계의 기본값이며 기존 필수 통제를 자동 완화하는 근거가 아니다.

## 작업 단위와 단일 작성자

메인은 사용자 요청의 범위가 정해졌을 때 요청 ID를 발급한다. 하위 태스크는 요청 ID와 로컬 태스크 ID를 함께 사용한다. 메인만 logs/prompts.jsonl, logs/files.jsonl, graph/edges.csv 및 공유 상태를 쓴다. 서브에이전트는 변경 파일·결과·근거·미해결 사항을 반환한다.

여러 파일을 바꾸는 한 작업은 한 레코드로 묶을 수 있다. 작업 마감 시 로그를 한 번 검증하고, 스키마 변경·검증 실패·의심되는 손상이 있을 때 추가 검증한다. append마다 전체 검증을 반복하지 않는다. 자동 생성된 임시·캐시 파일을 하나씩 대장에 등록하지 않는다.

## 기존 JSONL v2 호환

사용하는 JSONL은 UTF-8, 한 줄에 JSON 하나, append-only로 유지한다. 이전 행을 고치거나 정렬하지 않고 정정 레코드를 추가한다. 없는 사실·commit·근거를 만들어 채우지 않는다.

| 로그 | 필드 |
|---|---|
| logs/files.jsonl | ts, files[], summary, req_id, basis_ids[], verify, commit, schema |
| logs/prompts.jsonl | ts, req_id, prompt, response, outputs[], schema |

- ts: YYYY-MM-DD HH:MM. req_id: P-001처럼 세 자리 이상 숫자. schema: v2.
- files: 구체적 경로나 전체 디렉터리의 trailing slash. 와일드카드 대신 범위를 명시한다.
- basis_ids: 적용할 F-/D-/M- ID. 해당 없으면 빈 배열.
- verify: 실행한 검사·근거 경로 또는 명시적인 검증 없음. commit: 실제 hash 또는 미커밋.
- prompt: 요청의 재현에 필요한 내용. 비밀 값은 보존하지 않고 생략 사실을 표시한다. response는 결과 요약이면 충분하다.
- 스키마는 tools/worklog/worklog_schema.py가 정본이다. 연속 레코드에는 같은 P-ID를 쓸 수 있으나 다른 ID 뒤에 이전 ID를 다시 쓰는 형식은 현재 검증기가 받지 않는다. 과거 작업 재개 시 새 P-ID를 발급하고 요약에 이전 요청을 연결한다.
- legacy_note, orphan_reason 등 기존 선언적 예외는 유지한다. 스키마 변경은 기존 데이터와 검증기의 마이그레이션을 함께 다룬다.

사용 중인 로그만 다음과 같이 검사한다:
python tools/worklog/validate_worklog.py logs/files.jsonl logs/prompts.jsonl

## 결정과 현재 정본

graph/edges.csv를 사용하는 프로젝트는 F(발견), D(결정), M(매핑)의 상태와 근거를 기록한다. 상태는 open / fixed / verified / rejected / superseded / deferred다.

현재 코드·설계 문서는 현재 상태로 갱신한다. 중요한 결정 번복은 supersedes 관계 또는 프로젝트의 동등한 이력 방식으로 남긴다. 이미 발행된 과거 보고서는 현재 정본과 구분해 보존한다. 감사 범위에 대장 갱신이 포함됐을 때 메인이 결과를 병합해 반영한다.

fixed는 변경이 적용된 상태, verified는 명시한 검증이 실제 통과한 상태다. 검증 방법이 수동·로컬·CI 중 무엇인지 구별한다. 재현 가능한 버그에는 되돌렸을 때 실패하는 회귀 검사를 우선한다. 문구·서식·일회성 작업까지 음성 대조와 CI를 일괄 요구하지 않는다.

## 증거와 게이트

중요한 측정값에는 출처·조건·단위를 함께 남긴다. 재사용할 시험 결과는 가능한 기계 판독 형식으로 저장하되 기존 테스트 로그도 근거가 될 수 있다. 모든 코드 언급에 원문 인용을 요구하지 않는다. 실제 확인한 위치만 인용한다.

tools/graph_checks.py는 설정된 프로젝트만 사용한다. graph/checks_config.template.json의 예제를 실제 파일로 채우거나 불필요한 검사를 제거한 뒤 graph/checks_config.json으로 저장한다. 빈 예제 설정을 검사 성공으로 보고하지 않는다.

검사 실행의 종료코드와 품질 완료는 별개다. 이 검사기의 known_open 등록은 기존 위반의 식별이며 해결이 아니다. 데이터 손실·권한·필수 계약 등 완료를 막는 결함은 종료코드가 0이어도 완료로 선언하지 않는다. 비차단 미해결 항목만 영향과 이유를 공개하고 보류할 수 있다.

## 검토와 경로

검토는 변경된 범위와 위험에 맞춘다. 고위험 변경·중요 마일스톤에는 독립 검토를 고려하고, 변경 없는 범위를 무기한 재감사하지 않는다. 재검토는 실제 수정·새 결함·명시한 검토 기준이 있을 때 수행한다.

사용자 지정과 기존 정본 위치가 우선이다. 새 프로젝트의 선택형 기본값은 설계 rd/, 보고 reports/, 최종 독립 산출물 output_docs/, 사람 검토용 별도 자료 review_docs/다. 같은 내용을 여러 위치에 정본으로 복제하지 않는다. 기존 파일을 옮기기 위해 이 규약을 소급 적용하지 않는다.
