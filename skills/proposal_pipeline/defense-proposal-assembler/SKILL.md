# Defense Proposal Assembler — 최종 병합 + 수치 일관성 게이트

사용자가 지정한 입력 자료·출력 경로·파일명·형식·서식을 우선한다. 아래 경로·이름·스타일은 기본 예시이며 필수 프로젝트 구조가 아니다. 지정이 없으면 현재 작업공간에 설명적인 새 이름을 사용하고, 요청한 형식만 생성한다. 현재 요청이 허용한 작성·저장은 진행한다. 존재하는 프로젝트 규칙·로그 방식이 있으면 적용하되 별도 외부 규칙 파일을 요구하지 않는다.

섹션 스킬들은 장별 조각(pptx)만 생성하고 끝난다. 이 스킬이 조각을 **최종 제안서
1건**으로 만들고, 병합 과정에서 장 간 수치 충돌을 잡는다.

```
1~5장 pptx + figures/ + WBS_TBS  →  [수치 교차 검사]  →  통합 pptx (+ 요청 시 docx)
                                        ↓ 불일치 시
                                   consistency_report → 해당 섹션 스킬로 반송
```

---

## 입력 (모두 파일 기준)

사용자 지정 파일 목록·메타데이터에서 section과 파일 경로를 대응시킨다. 아래는 기본 5장 구성의 예시 이름이다. 다른 이름·폴더·형식도 받을 수 있으며, 사용자/RFP 목차가 다르면 그 목차의 필수 section을 기준으로 누락을 검사한다.

| 파일 | 생산 스킬 | 필수 |
|---|---|---|
| `[과제명약어]_과제개요.pptx` | defense-proposal-writer(section=overview) | ✅ |
| `[과제명약어]_연구개발방안.pptx` | defense-proposal-writer(section=rd-plan) | ✅ |
| `[과제명약어]_기술현황분석.pptx` | defense-proposal-writer(section=tech-analysis) | ✅ |
| `[과제명약어]_연구계획.pptx` | defense-proposal-writer(section=research-plan) | ✅ |
| `[과제명약어]_세부연구계획.pptx` | defense-proposal-writer(section=detail-plan) | ✅ |
| `figures/`, `[과제명약어]_WBS_TBS.pptx`/`.xlsx` | defense-diagram / defense-wbs-tbs | 선택 |
| `*_kpi_benchmark_[과제명약어].md` | defense-kpi-benchmark | ✅ (일관성 기준값) |
| `*_proposal_prep_[과제명약어].md` | defense-proposal-prep | 선택 (TRL 기준값) |

필수 장이 누락되면 해당 파일 또는 `defense-proposal-writer`의 section 작성을 연결한다. 요청이 초안 패키징이면 누락 장과 상태를 명시한다. filename만으로 과제를 판정하지 말고 제목·과제 식별자·출처 메타데이터를 대조한다.

## 실행 단계

### Step 1 — 수치 일관성 교차 검사 (병합 전 게이트)

pptx 텍스트를 추출(pptx 스킬 활용)하여 아래 항목을 장 간 대조한다:

| 검사 항목 | 기준(정본) | 대조 대상 |
|---|---|---|
| KPI 항목·목표치 | `*_kpi_benchmark_*.md` 산출표 | 1장 3항, 2장, 4장 성과평가, 5장 성능시험 |
| TRL 현재/목표 | `*_proposal_prep_*.md` | 1장, 3장 |
| 총연구기간·단계 구분 | 1장 추진계획 | 4장 일정, WBS 간트 |
| 총예산·연차 배분 | 5장 예산 총괄 (정본) | 1장 개요, 4장 개략 배분 |
| 세부과제 명칭·개수 | WBS | 4장 세부과제 계획, 5장 |
| `[SYNTHETIC-RFP]` 태그 | RFP/prep 헤더 | 태그 존재 시 최종본 표지에 승계 |

- 불일치 발견 → `[MISMATCH: <항목> — <장A>=<값> vs <장B>=<값>, 정본=<값>]`
- **게이트 규칙**: MISMATCH가 1건이라도 있으면 병합 중단이 기본. 리포트를 제시하고
  해당 섹션 스킬로 수정을 반송한다. 사용자가 "그대로 병합"을 명시하면 진행하되
  최종본 부록에 미해결 불일치 목록을 포함한다.

### Step 2 — 병합

- 슬라이드 순서: 표지 → 목차 → 1장 → 2장 → 3장 → 4장 → 5장 → 부록(WBS/TBS xlsx 요약, figures 인덱스)
- 표지: 과제명, 기관, 날짜, (해당 시) `[SYNTHETIC-RFP]` 태그
- 서식 통일: 사용자 지정 양식을 우선하고, 없으면 1장 기준으로 정규화한다. 슬라이드 번호를 재부여한다.
- pptx 병합은 **pptx 스킬**의 방법을 따른다 (직접 XML 조작 금지)

### Step 3 — 산출

| 파일 | 위치 |
|---|---|
| `[과제명약어]_제안서_최종_vN.pptx` | 사용자 지정 출력 위치 |
| `YYMMDD_HHMM_consistency_report_[과제명약어].md` | 사용자 지정 검토 보고 위치 |
| (요청 시) `[과제명약어]_제안서_최종_vN.docx` | 사용자 지정 출력 위치 |

Step 1의 일관성 결과를 반영하여 현재 요청에서 허용한 최종본을 생성한다.
미해결 불일치는 게이트 규칙대로 처리하고, 파일 로그는 요청되거나 대상 프로젝트에 지정된 경우 기록한다.

## 작업 규칙

- 수치는 절대 이 스킬에서 수정하지 않는다 — 불일치는 원 섹션 스킬로 반송 (수정 주체 유지).
- 버전 관리: 재병합 시 `vN` 증가, 이전 버전 삭제 금지.
- 다과제 안전: 파일 내용·출처·과제 식별자로 같은 과제임을 확인한다. 충돌하는 파일은 근거와 함께 제외하고 보고한다. 사용자가 정한 파일명을 강제로 바꾸지 않는다.
