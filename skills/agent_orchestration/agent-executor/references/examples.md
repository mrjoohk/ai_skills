# 실행 예시

## 간단한 요청
입력: 설정 값 하나 바꾸고 확인.
실행: main이 직접 처리. 계획 파일 부재 오류·서브에이전트·별도 보고서 없음.

## 준비된 태스크 실행
입력: T1과 T2가 독립, T3은 둘의 검증된 결과를 필요로 함.
실행: 런타임 용량이 되면 T1/T2를 동시에 맡기고 main은 통합 준비. 필수 기준을 확인한 뒤 T3 실행. 용량이 부족하면 일부를 main이 처리하거나 순차 실행.

## 공유 정본
입력: GPU·물리 감사가 같은 domain_metrics.md를 갱신할 필요가 있음.
실행: 각 worker는 별도 근거·지표 조각을 반환. main이 충돌을 확인하고 정본을 한 번 병합.

## 부분 실패
입력: T1 출력은 생성됐으나 계약 검증 실패, T2는 독립 조사.
실행: T1 의존 작업은 보류하고 원인을 수정. T2는 계속. 외부 권한이 필요할 때만 main이 사용자에게 요청.

## 재개
입력: 이전 설계가 완료됐고 구현만 남음.
실행: 기존 산출물과 기준을 확인해 구현 태스크만 재개. 완료된 모든 worker를 다시 실행하지 않음.
