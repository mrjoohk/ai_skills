# 메인·서브에이전트 실행

현재 메인 에이전트가 사용자 범위·공유 결정·통합·최종 결과를 책임진다. agent-orchestration의 계획 파일 또는 대화의 간단한 태스크 계약을 입력으로 사용한다. 사용자가 실행을 요청했다면 계획 파일이 없다는 이유로 멈추지 않고 필요한 최소 계약을 만든다.

## 실행

1. 요청의 완료 기준·현재 승인·실제 입력을 확인한다. 이미 끝난 단계와 결과를 재사용한다. 짧거나 분리 이점이 없는 작업은 직접 수행한다.
2. 위임할 태스크의 목표·입력·의존 수락 조건·쓰기 범위·출력/반환·검증 기준을 확인한다. 누락으로 실제 모호해지는 부분만 보완한다.
3. 현재 환경의 생성·메시지·상태·대기 도구를 사용한다. 하위 에이전트 기능이 없으면 메인이 순차로 처리하며 위임한 것처럼 보고하지 않는다.
4. 준비된 독립 태스크를 가용 슬롯 안에서 시작한다. 메인 포함 실행 한도와 추가 fanout을 함께 계산한다. 같은 파일은 한 명만 쓴다. 공유 파일이 격리되지 않으면 고유 조각을 반환받거나 순차 처리한다.
5. 메인은 worker가 맡지 않은 critical path 작업·입력 점검·통합 준비를 이어간다. 실제 진행·출력 변경·차단에 따라 메시지로 범위를 조정할 수 있다. 변경 없는 상태를 반복 조회하지 않는다.
6. 결과를 받으면 실제 변경·내용·검사·수락 기준을 확인한다. PASS라는 말이나 파일 존재만으로 의존 태스크를 시작하지 않는다.
7. 필요한 통합 검사를 마친 뒤 사용자에게 결과·검증·남은 한계를 보고한다. 별도 보고서는 요청됐거나 장기 인계·추적에 필요할 때만 저장한다.

## 반환과 실패

worker는 status(COMPLETE/PARTIAL/BLOCKED/FAILED), 실제 outputs, summary, checks, findings/blockers를 반환한다. 기존 계획의 STATUS/OUTPUTS 형식도 실제 증거와 함께 해석할 수 있다. 파이프라인의 별도 JSON validator 계약이 있으면 해당 필드에 매핑한다.

필수 수락 기준 미달은 관련 의존 태스크를 보류한다. advisory만 남았으면 영향과 이유를 밝혀 진행할 수 있다. 실패 원인을 확인해 범위 안에서 수정·재배정하고 독립 작업은 계속한다. 새 근거 없이 같은 재시도를 반복하지 않는다. 권한·필수 정보·범위 결정은 메인에게 올리고, 메인이 필요한 질문만 모아 사용자에게 전달한다.

위임은 이미 받은 승인·제약을 승계하며 새 권한을 만들지 않는다. worker가 직접 공유 ID·전역 로그·대장을 쓰거나 팀을 무제한 확장하지 않게 한다.
