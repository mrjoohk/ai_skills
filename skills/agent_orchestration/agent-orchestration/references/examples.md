# 태스크 배분 예시

## 작은 수정
요청: README의 잘못된 경로 하나 수정.
처리: 메인이 수정하고 실제 링크를 확인. 역할 문서·worker·추가 승인 없음.

## 독립 구현
요청: 서로 다른 두 importer를 추가하고 함께 연결.
처리: 메인이 공통 계약을 정한다. worker는 각 importer와 그 시험만 수정하고, 메인이 공통 등록 파일·통합 검사를 담당한다. 공통 계약이 바뀌면 관련 태스크를 조정한 뒤 진행한다.

## 조사와 집필
요청: 근거를 비교해 제안 문서 작성.
처리: worker에게 자료 범위·출처 기준·반환 형식을 맡기고 메인은 기존 문서 구조·사용자 요구를 정리한다. 조사 수치가 필요한 본문은 근거 수락 후 채운다.

## 독립 검토
요청: 중요한 파일 변환 변경을 검토까지 마무리.
처리: 구현자는 고유 범위를 수정하고 검토자는 확정 diff와 수락 기준을 읽는다. 메인이 지적을 재현·채택해 수정하고 영향 범위만 재확인한다. 새 근거나 변경 없이 감사 전체를 반복하지 않는다.

## 장기 계획
요청: 여러 단계 작업을 나눠 진행하고 다음 세션에서도 이어가기.
처리: agents/orchestration_plan.md에 태스크·의존성·writer·완료 기준·현재 상태를 저장하고 각 위임에는 필요한 입력만 전달한다. 사용자 요청 없이 별도 채팅을 만들 필요는 없다.
