# 태스크 분해와 역할 설계

메인은 요청의 해석·공유 결정·통합·최종 검증을 책임진다. 이 스킬은 태스크와 배분을 정하며, 실제 위임 실행에는 agent-executor 또는 현재 런타임의 동등한 기능을 사용한다. 사용자가 실행을 요청했다면 계획 작성만으로 끝내지 않는다.

## 분해 기준

1. 요청한 결과·기존 승인·완료 기준과 실제 입력을 확인한다. 작은 수정이나 의존성이 강한 작업은 메인이 직접 처리한다.
2. 독립 조사, 분리 가능한 구현, 다른 관점의 검토처럼 위임 이점이 있는 태스크만 나눈다. Architect·Builder·Verifier는 역할 예시이며 필수 인원수가 아니다.
3. 각 태스크에 목표, 입력·기준점, 출력/반환, 의존성, 쓰기 범위, 완료·검증 기준을 붙인다. 자료가 부족하면 가정과 차단 조건을 구분한다.
4. 같은 파일의 writer를 하나로 정한다. 다른 작업자는 고유 조각이나 findings를 반환하고 소유자가 병합한다. 공유 로그·대장·정본은 메인 또는 지정된 한 명이 갱신한다.
5. 의존성의 수락 조건을 만족한 태스크만 시작할 수 있게 한다. 병렬 인원은 런타임 가용 슬롯과 메인 용량을 함께 고려하며, 재위임은 메인의 조정 없이 인원을 늘리는 수단으로 쓰지 않는다.

짧은 계획은 현재 대화의 태스크 요약으로 충분하다. 파일을 요청했거나 장기 재개·여러 작업자 조정에 도움이 될 때만 [역할 템플릿](assets/agent-role-template.md)과 [계획 템플릿](assets/orchestration-plan-template.md)을 사용한다. 기본 저장 위치는 agents/이며 기존 프로젝트 위치를 우선한다. 파일이 없다는 이유로 이미 허용된 작업을 멈추지 않는다.

## 배분과 실행 연결

메인 직접 작업, 준비된 독립 태스크, 의존 입력을 기다리는 태스크를 구별한다. 위임한 뒤 메인은 같은 일을 반복하지 않고 critical path의 미위임 작업이나 통합 준비를 진행한다. 작업량보다 계획·전달·검토 비용이 커지면 태스크를 합치거나 직접 처리한다.

검토자는 필요한 기준점과 검증 범위를 받는다. 독립 검토가 필요하면 작성자의 결론에 끌리지 않게 실제 입력·diff·기준을 제공한다. 검토 중 입력을 바꾸면 기준점을 갱신해 알린다.

실제 실행·수집·실패 처리는 [agent-executor](../agent-executor/SKILL.md), 세부 계약은 [reference](references/reference.md), 판단 예시는 [examples](references/examples.md)를 참조한다. REQ→IF→UF 전체 설계 파이프라인을 선택한 경우에만 [engineering manifest](references/engineering-manifest.md)를 추가로 읽는다.
